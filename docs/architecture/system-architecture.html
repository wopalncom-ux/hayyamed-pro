1. Architecture Overview

Hayya Med Pro is a multi-tenant healthcare SaaS platform built on a cloud-native stack. The architecture prioritizes security (healthcare data), scalability (designed for 100K+ users from day one), offline capability (PWA + service worker), and global expansion readiness (rules engine, not hardcoded logic).

AI Governance Rules (Non-Negotiable)

No PII in prompts — professional_id only, never name or license number
Zod validation — every AI response validated against schema before use
Versioned prompts — all prompts live in lib/ai/prompts/ — never inline
Fallback required — rule-based fallback for all AI routes — compliance cannot depend on AI uptime
Audit every call — model, tokens, latency, professional_id, action logged
Tier gate — Free tier: 0 AI calls. Pro: Haiku+Sonnet. Enterprise: Opus

5. Security Architecture

Non-Negotiable Security Rules

Every API route starts with supabase.auth.getUser() — no exceptions, ever. If this check fails, the route returns 401 immediately.
Admin routes additionally verify role — via organization_members table, not JWT claims alone.
Service role key used only server-side — never exposed to client, never in API response.
Certificate storage: private bucket, signed URLs only — 1-hour expiry. No public bucket access.
Path traversal protection — block .., \0, // on all file operations.
RLS enabled on every table — no exceptions. Verified in Session 47 RLS audit (8/8 tests passed).
Audit logs append-only — no UPDATE or DELETE policy on audit_logs. 7-year retention.
Rate limiting — Upstash Redis on auth, AI, and webhook endpoints. Token rotation required.
