Apple Pay & Subscription Readiness

Current state, App Store compliance analysis, and recommended integration path

Current Payment Architecture

LayerStatusDetail
QIIB (primary)Pending credsFull integration built. Graceful fallback active ("contact support"). Awaiting QIIB merchant services to provide API credentials.
Paddle (secondary)Not required yetIntegration code present. Not required at launch — QIIB is primary.
Web checkout onlyCorrectAll subscriptions via web browser. No in-app purchase SDK installed. This is the correct Apple App Store strategy.

Apple Pay Web Integration Options

OptionRiskRecommendation
Option A: Apple Pay JS on web (hayyamed.pro) Low Risk Safe to implement on the web app. Requires Apple Developer account, merchant domain verification, and payment processor support (Stripe or Paddle support Apple Pay). No App Store impact.
Option B: Apple Pay via Paddle on web Low Risk Paddle supports Apple Pay natively in their checkout. When Paddle is activated, Apple Pay can be enabled in Paddle Dashboard settings. Zero additional code.
Option C: In-app purchase in iOS app HIGH RISK — DO NOT Would require Apple StoreKit integration and 30% Apple commission on all subscriptions. Platform is correctly using the "reader app exemption" which forbids in-app purchases but allows web-initiated subscriptions.
Option D: Google Pay on web Low Risk Google Pay on the web is safe. Can be added via Google Pay API when Paddle is activated (Paddle supports Google Pay). No Play Store impact.

✅ Current strategy is correct — do not change

The current architecture (web-only checkout, no in-app purchase) is the safest and most profitable approach for a subscription SaaS healthcare app on iOS and Android. Apple takes 30% on in-app purchases but 0% on web-initiated subscriptions. The reader app exemption explicitly permits this pattern (Spotify, Netflix, and hundreds of SaaS apps use it). Recommended next step for payments: activate Paddle and enable Apple Pay and Google Pay in Paddle Dashboard — zero code required.

⚠️ Action required: QIIB credentials

The QIIB payment integration is fully built and deployed. The only missing piece is the merchant API credentials from QIIB. Contact QIIB merchant services and request: QIIB_MERCHANT_ID, QIIB_API_KEY, QIIB_BASE_URL, and QIIB_WEBHOOK_SECRET. Once received, store in GCP Secret Manager and trigger a Cloud Build deploy.
