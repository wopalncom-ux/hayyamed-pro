💳 Apple Pay / Subscription Analysis

Recommended path (zero code): Activate Paddle account → navigate to Paddle Dashboard → Payment Methods → enable Apple Pay + Google Pay. Paddle handles the entire payment flow including device detection. No code changes required.
TopicAnalysisRiskAction
Apple Pay via Paddle Paddle's checkout overlay natively supports Apple Pay on Safari/iOS. User taps Upgrade → Paddle overlay → Apple Pay sheet. Zero Stripe/custom code needed. Low Enable in Paddle Dashboard
Google Pay via Paddle Same as Apple Pay — Paddle overlay auto-detects Android Chrome and shows Google Pay button. Low Enable in Paddle Dashboard
App Store 30% fee Current architecture: web-only checkout. No in-app purchases. Reader App Exemption applies (CME tracking is a reader/productivity app). Paddle subscription = 0% App Store fee. No risk Keep web-only checkout
In-app purchase via StoreKit NOT recommended. Apple takes 30%. Violates our architecture. Would require separate pricing for App Store users. High Do NOT implement
Payment success/failure states Paddle webhooks exist. /api/webhooks/paddle handles subscription.created, subscription.updated, subscription.cancelled. UI states for success/failure need dedicated pages. Medium Add /billing/success and /billing/failed pages
Invoice/receipt flow Paddle auto-generates PDF invoices and emails them. Link in /dashboard/billing page to Paddle customer portal. Low Already handled by Paddle
