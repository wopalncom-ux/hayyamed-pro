Flow 1 — User Registration & Onboarding

✓ Live Supabase Auth DB Trigger Postmark PostHog
A new user registers → Supabase Auth creates the user → email verification sent → DB trigger auto-creates professional_profiles + cme_wallets + privacy_settings rows → 7-step onboarding completes → professional lands on dashboard. Activation event fires in PostHog.
Trigger: User submits /register form with email + password
flowchart TD A([/register form submitted]) --> B[Supabase Auth: createUser] B --> C{Email verified?} C -->|No| D[Postmark: verification email] D --> E[/verify-email click] E --> F[Mark confirmed] C -->|Yes| G[DB Trigger: handle_new_user] G --> H[Insert professional_profiles] H --> I[Insert cme_wallets] I --> J[Insert profile_privacy_settings] J --> K[Redirect → /onboarding/1] K --> L[7-step onboarding] L --> M[Step 7: compliance disclaimer] M --> N[onboarding_complete = true] N --> O[Redirect → /dashboard] O --> P[PostHog: user_activated event]

Flow 2 — CME Activity Submission

✓ Live Supabase Storage Vertex AI (Vision) DB Trigger
User uploads a CME certificate → AI OCR (Pro/Employer) auto-extracts fields → user confirms → activity is logged → verifier approves → DB trigger syncs credits to wallet → compliance status recomputed. Offline submissions are queued and auto-synced on reconnect.
Trigger: User opens AddActivityModal and uploads certificate file
flowchart TD A([User clicks Add Activity]) --> B[AddActivityModal opens] B --> C{Online?} C -->|No| D[Queue in localStorage] D --> E[Auto-flush on reconnect] C -->|Yes| F[Upload to Supabase Storage private bucket] F --> G{Pro/Employer tier?} G -->|Yes| H[POST /api/ai/ocr-certificate] H --> I[Vertex AI: Claude Sonnet Vision] I --> J[Extract: title, date, credits, accreditor] J --> K[Zod validate AI output] K --> L[Auto-populate form] G -->|No — Free| L L --> M[User confirms and submits] M --> N[Insert cme_activities — pending] N --> O[Admin verifies] O -->|Approved| P[DB Trigger: sync credits to cme_wallets] P --> Q[Compliance status recomputed] Q --> R[Push notification: credits added] O -->|Rejected| S[Postmark: rejection email with reason]

Flow 3 — Credit Assignment & Wallet Sync

✓ Live DB Trigger (Postgres) Rules Engine PostHog
When a CME activity is verified, a Postgres trigger fires automatically. It reads the country rules engine for category caps, applies the correct credit value, updates the wallet totals, and recomputes compliance_status. Zero application-layer code involved.
Trigger: UPDATE on cme_activities WHERE status changes to 'verified'
flowchart TD A([cme_activities.status = verified]) --> B[Postgres Trigger fires] B --> C[Read activity: credits, category, country] C --> D[Lookup country_compliance_rules for category cap] D --> E{Category cap reached?} E -->|Exceeded| F[Apply cap limit only] E -->|Under cap| G[Apply full credits] F --> H[UPDATE cme_wallets: credits_completed += N] G --> H H --> I[Recompute compliance_status] I --> J{credits_completed >= required?} J -->|Yes| K[status = compliant] J -->|No| L[status = in_progress or at_risk] K --> M[Insert audit_log row] L --> M M --> N[PostHog: compliance_updated event]

Flow 4 — License Expiry Alert Automation

✓ Live — GCP Cloud Scheduler Postmark Web Push Audit Log
Two separate GCP Cloud Scheduler jobs — cme-deadline (08:00 AST) and license-expiry (09:00 AST) — scan all professionals daily and send tiered alerts based on days to deadline. 90/60/30/14/7 day thresholds, both email and push.
Trigger: GCP Cloud Scheduler — daily 08:00 and 09:00 AST (UTC+3)
flowchart TD A([GCP Scheduler 09:00 AST]) --> B[GET /api/cron/license-expiry] B --> C[Verify CRON_SECRET header] C --> D[Query professional_profiles: license_expiry within 90 days] D --> E{Days to expiry?} E -->|90 days| F[Postmark: renewal prep email] E -->|60 days| G[Postmark: 60-day checklist email] E -->|30 days| H[Postmark: urgent alert email] E -->|14 days| I[Postmark + Web Push: critical alert] E -->|7 days| J[Postmark + Web Push: final warning] E -->|Expired| K[Dashboard: license lapsed banner] F --> L[Audit log: reminder_sent] G --> L H --> L I --> L J --> L K --> L

Flow 5 — Compliance Gap Monitoring

✓ Live — GCP Cloud Scheduler Vertex AI (Claude Sonnet) Postmark Web Push
Daily scan of all CME wallets assesses compliance risk. At-risk professionals receive AI-generated personalized action plans via email and push. The AI recommendation is generated via Vertex AI (Claude Sonnet) — anonymized, no PII in prompt.
Trigger: GCP Cloud Scheduler — daily 08:00 AST
flowchart TD A([GCP Scheduler 08:00 AST]) --> B[GET /api/cron/cme-deadline] B --> C[Verify CRON_SECRET] C --> D[Scan all cme_wallets] D --> E[Calculate: days to cycle end + completion %] E --> F{Risk level?} F -->|at_risk| G[Postmark: gap warning email] F -->|critical| H[Postmark + Web Push: urgent alert] G --> I[POST /api/ai/compliance-recommendations] H --> I I --> J[Anonymized prompt: professional_id + gaps + country] J --> K[Vertex AI: Claude Sonnet 4.6] K --> L[Zod validate structured response] L --> M{AI available?} M -->|Yes| N[Store recommendations in DB] M -->|No| O[Rule-based fallback — no AI dependency] N --> P[AIRecommendationsCard updated in dashboard] O --> P

Flow 6 — Marketplace Course Enrollment

✓ Live Plan Gate (server-side) DB Trigger MilestoneCelebration
User enrolls in a marketplace course → plan entitlement checked server-side → enrollment recorded → on completion, DB trigger auto-syncs credits to cme_activities → wallet updates → milestone animation fires. Gamification is triggered by DB state, not UI logic.
Trigger: User clicks Enroll on a marketplace course
flowchart TD A([/dashboard/marketplace course click]) --> B[POST /api/marketplace/enroll] B --> C[supabase.auth.getUser — auth check] C --> D{Plan entitlement?} D -->|Free limit reached| E[Upgrade wall → /pricing] D -->|Allowed| F[Insert course_enrollments row] F --> G[User completes course] G --> H[POST /api/marketplace/complete] H --> I[Update enrollment: completed_at, status = completed] I --> J[DB Trigger: auto-create cme_activities row] J --> K[DB Trigger: sync credits to cme_wallets] K --> L[Compliance status recomputed] L --> M[MilestoneCelebration component fires] M --> N[PostHog: course_completed event]

Flow 7 — AI Compliance Recommendations

✓ Live Vertex AI — Claude Sonnet 4.6 Zod Validation Plan Gate
Pro/Employer users get AI-generated compliance recommendations. Free users get rule-based fallback. No PII in prompts — professional_id only. Fallback is always available so compliance never depends on AI uptime. All calls logged: model, tokens, latency.
Trigger: Dashboard AI tab loads or explicit request
flowchart TD A([Dashboard AI tab loads]) --> B[Fetch compliance gaps from cme_wallets] B --> C[POST /api/ai/compliance-recommendations] C --> D[supabase.auth.getUser] D --> E{Plan tier?} E -->|Free| F[Return rule-based fallback — 0 AI cost] E -->|Pro or Employer| G[Build anonymized prompt] G --> H[professional_id + gaps + country — NO PII] H --> I[Vertex AI: Claude Sonnet 4.6] I --> J[Streaming response] J --> K[Zod validate structured output] K --> L{AI available?} L -->|No| M[Rule-based fallback response] L -->|Yes| N[Top 3 course recommendations + gap analysis] N --> O[Log: model, tokens, latency, professional_id, action] M --> P[AIRecommendationsCard renders in dashboard] N --> P

Flow 9 — Subscription Payment Lifecycle

Integrated — Paddle Approval Pending Paddle Webhooks Postmark PostHog
User upgrades → Paddle checkout overlay → on success Paddle fires a signed webhook → subscription activated → plan updated in DB → welcome email sent → Pro features unlocked. Webhook signature verified before any DB write.
Trigger: User clicks Upgrade to Pro on /pricing or upgrade wall
flowchart TD A([User clicks Upgrade]) --> B[POST /api/paddle/checkout] B --> C[supabase.auth.getUser] C --> D[Check discount code — /api/discounts/validate] D --> E[Paddle: create checkout session] E --> F[Paddle checkout overlay opens] F --> G{Payment outcome} G -->|Cancelled| H[Return to pricing — no change] G -->|Success| I[Paddle webhook: POST /api/paddle/webhook] I --> J[Verify Paddle webhook signature] J --> K[subscription_activated event type] K --> L[Upsert subscriptions row] L --> M[Update professional_profiles: plan = pro] M --> N[Postmark: welcome Pro email] N --> O[PostHog: subscription_started event] O --> P[Dashboard: Pro features unlocked instantly]

Flow 10 — AI Certificate OCR

✓ Live Vertex AI — Claude Sonnet Vision Zod Validation Plan Gate
Pro/Employer users photograph their CME certificate → Claude Vision (Vertex AI) extracts structured data → Zod validates → form auto-populated. Supports Arabic and English certificates. No PII sent to AI — certificate content only, not user identity.
Trigger: User uploads certificate image in AddActivityModal
flowchart TD A([User uploads certificate image]) --> B{Plan: Pro or Employer?} B -->|No — Free| C[Manual form entry only] B -->|Yes| D[POST /api/ai/ocr-certificate] D --> E[supabase.auth.getUser] E --> F[Read image from Supabase Storage] F --> G[Vertex AI: Claude Sonnet 4.6 multimodal] G --> H[Extract: title, date, provider, accreditor, credits, language] H --> I[Zod schema validation of AI output] I --> J{Valid extraction?} J -->|No| K[Return empty — user enters manually] J -->|Yes| L[Auto-populate activity form fields] L --> M[User reviews in 3 seconds] M --> N[User submits — fast logging] N --> O[Log: model, tokens, latency, professional_id]

Flow 11 — Push Notification Dispatch

✓ Live VAPID Web Push push_subscriptions table Service Worker
Web Push uses VAPID keys. Subscriptions stored in push_subscriptions table. Service worker registered at install. Notifications dispatched from cron routes or event triggers. iOS Safari (PWA) and all desktop browsers supported.
Trigger: Cron alert, CME verification, or critical compliance event
flowchart TD A([User installs PWA or visits dashboard]) --> B[Service Worker registers] B --> C[Push permission prompt — user approves] C --> D[POST /api/push/subscribe] D --> E[Insert push_subscriptions row: endpoint + keys] F([Cron or compliance event fires]) --> G[POST /api/push/send] G --> H[supabase.auth.getUser or CRON_SECRET] H --> I[Query push_subscriptions for target users] I --> J[VAPID: sign + send Web Push] J --> K{Delivery status} K -->|410 Gone| L[Delete stale subscription from DB] K -->|Success| M[Notification appears on device] M --> N[Click → deep link to relevant dashboard page]
